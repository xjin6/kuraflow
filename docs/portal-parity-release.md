# 三端工具栏、平台员工与独立功能配置

本说明记录 2026-10-25 这轮改动的实现范围、权限和迁移要求。本轮已发布为 `0c58e2f5-ca57-4230-bf52-00ccf39cf06d`；实际线上版本与发布验收结果以 [cloud-deployment-status.md](cloud-deployment-status.md) 为准。

## 三端界面

- 顶部工具统一按 **Flow → 语言 → 通知** 排列，共用 `src/ui/topbar-tools.js`。三端均有实际功能入口，停用时保持可见并置灰。
- 点击区域统一为 34×34 px，常态没有边框或底衬。悬停、键盘聚焦、展开时使用所属端主题色 12% 透明度底衬；平台紫、管理蓝、门店橙的对应关系不变。
- 通知图形为 18×18 px，并向下微调 0.5 px，以光学中心对齐另外两个 20×20 px 图形。未读红色气泡不改变按钮尺寸。
- 手机平台端的跨端入口放在侧栏，避免英文／越南语长标签把通知挤出顶部；桌面仍保留原入口。已在 1280×720 和 iPhone Air 420×912 核对三端，平台手机负责人／管理员登录切换保持框高及按钮位置。
- 三端侧栏去掉「客户服务」「门店服务」等导航分区小字，顶部去掉「已连接」。
- 管理端菜单和页面标题统一为「月结统计」。
- 平台客户列表只显示名称，名称与头像垂直居中，不再附加「门店与账号」。点击客户默认进入「员工管理」，第二个页签为「合作门店」。
- 平台的个人入口也位于左下角，进入平台自己的员工管理／我的账号，不提供客户或门店选择器。

## 平台员工

平台登录现在提供私有密钥和管理员账号密码两种方式。平台负责人仍使用已有私有密钥；新增管理员沿用共享账号表单，可填写姓名、联系方式、账号名和初始密码，创建后可通过员工行编辑头像，人数不限。

| 能力 | 平台负责人 | 平台管理员 |
| --- | --- | --- |
| 查看客户、门店及允许展示的员工资料 | 可以 | 只读 |
| 修改本人的账号、密码、姓名、联系方式和头像 | 沿用负责人适用的头像入口，密钥不回显 | 可以，修改登录资料后重新登录 |
| 新增、编辑、停用、启用、删除或恢复平台管理员 | 可以 | 不可以 |
| 修改客户及功能配置、重置下辖登录凭据、修改他人头像 | 可以 | 不可以 |
| 查看原始操作记录 | 可以 | 不可以 |
| 查看自己的通知与允许的 Flow 查询 | 可以 | 可以 |

平台管理员与厨房、门店账号使用独立的角色范围，`tenant_id` 与 `store_id` 均为空。平台密钥不展示、不复制、不因本次改动轮换。密码继续使用现有散列存储。

管理员删除沿用软删除，立即停用并撤销会话；恢复后仍停用，需明确启用。负责人身份不能删除。账号生命周期操作检查版本、负责人当前状态和归属；普通成员的资料更新不会修改角色或组织范围。

## 六个独立开关

平台负责人在每个客户的功能配置中分别设置：

| 功能 | 管理端 | 门店端 |
| --- | --- | --- |
| Flow | 独立启用／停用 | 独立启用／停用 |
| 多语言 | 独立启用／停用 | 独立启用／停用 |
| 通知 | 独立启用／停用 | 独立启用／停用 |

六项配置与已有模型配置共用版本校验，整组原子保存。关闭某一项不会静默修改另一端。`GET /api/ui-features` 根据当前登录身份返回有效策略，不接受请求参数指定其他租户或门店。

兼容默认值：管理端 Flow 保留原设置；新门店 Flow 默认关闭；两端多语言在尚未单独配置时继承原厨房设置；两端通知默认开启。平台自身语言和通知保持可用，其 Flow 单独配置。发布不自动开启 AI，也不复制已有厨房的令牌。

## Flow 的数据和执行范围

| 端 | 查询范围 | 业务写入 |
| --- | --- | --- |
| 管理端 | 当前厨房的业务数据及完整历史 | 保留现有待确认卡片，用户点击确认后执行 |
| 门店端 | 本店可订购且有有效单价的商品、本店订单与单据 | 当前只读；服务端拒绝操作与确认接口 |
| 平台端 | 权限内客户、合作门店和账号摘要；平台成员只读取自己的 Flow 账号记录 | 当前只读；服务端拒绝操作与确认接口 |

门店 Flow 复用仓储层的安全投影，并分页读取本店完整已送达订单历史。不返回采购成本、内部配货备注、其他门店价格、负责人码或未报价目录商品。平台 Flow 不读取客户聊天、业务价格或登录凭据，只将允许的摘要字段提供给模型。

平台自己的模型连接使用内部 `@platform` 命名空间，不创建同名客户、不借用客户连接。平台负责人可从自身 Flow 面板打开配置；未连接模型前界面明确提示尚未配置。厨房的管理端与门店端共用该厨房由平台配置的连接和固定模型，但是否允许使用 Flow 分别受各端开关控制。

聊天、草稿、图片、附件和并发请求锁按端、厨房、门店和个人隔离。原管理端存储键保持兼容，新增门店键包含门店与个人身份，平台使用独立空间。附件是数据，不能改变工具权限；平台与门店上传附件后仍只读。

后台在工具执行、结果输出和生成过程定时复核登录状态、功能开关与固定模型。平台关闭功能或账号被停用后，生成会停止。凭据仅由服务端读取并加密保存，配置响应不回显令牌。

## 通知范围

- 管理端保留已有业务通知；阅读不会改变订单、库存、缺货或待办状态。
- 门店端只接收本店下单、配货完成、开始配送、送达及催单等公开节点。通知正文不复用含内部备注的管理端正文。
- 平台端从真实 `account_audit` 记录生成允许展示的摘要，可进入对应客户或平台员工页，不返回凭据或原始审计载荷。
- 三端已读记录均按个人账号保存。关闭某端通知后，API 拒绝读取和标记，界面清除旧气泡并忽略尚未完成的旧请求结果。

## 迁移与发布要求

本轮新增两项增量迁移，前置是现有迁移已应用至 `0014_multilingual.sql`：

| 迁移 | 作用 | 保留行为 |
| --- | --- | --- |
| `0015_portal_features.sql` | 新增 `tenant_portal_features` 和平台自身的 `platform_features` | 保留已有管理端 Flow、多语言和连接；平台 Flow 初始关闭，新门店 Flow 默认关闭 |
| `0016_portal_notifications.sql` | 为已有真实审计记录建立稳定通知引用，并为后续审计建立引用触发器；新增个人已读记录 | 不改已有租户通知、账号、业务记录或凭据；不复制原始审计载荷 |

平台管理员复用现有账号表，不需要账号结构迁移。新功能不会自动创建任何生产管理员。

发布前需核对固定账号、Worker、D1、KV 绑定并保留数据库与发布快照，再应用这两项迁移。发布不得顺带重建数据库、导入演示记录、轮换密钥或复制本地授权。项目内 Wrangler 使用 `--profile kuraflow`；线上回执与资源验证完成后，才更新部署状态文档。
