# 门店结算、月结统计与订单 PDF（本地待 review）

- 门店卡片压缩头部/字段/底部间距，字号不变，操作顺序为「编辑 / 结算 / 报价」。
- 报价表的「查看依据」按钮移除，同时移除保存报价后对该按钮的旧 DOM 更新。
- 月结与统计读取当前 KitchenModel 的 orders/stores/products：按门店和配送月份筛选，逐单明细、月度汇总、下钻订单。木屋等手动新增门店与订单无需导入静态业务资料即可参与。历史导入单据放到折叠区，绝不并入实时订单金额重复统计。
- 默认为真实订单，管理员可勾选演示订单。商品数量与单价使用订单已保存的快照，品名规格按已有订单字段/商品元数据回填；未报价与税口径未知时保留待确认，不视为零税、不套用参考 PDF 的 8%。不推断付款状态。
- PDF 采用 A4 竖版纳品书结构，含收货门店、地址/联系人、开票方、发行日、配送日、订单号、商品数量/单位/单价/金额、税额及运费状态。自动分页并重复表头。浏览器本地生成，可从结算列表、详情弹窗和货单详情导出。门店端只可导出本店订单。
- 字体采用 OFL Noto Sans SC 的静态子集，改名 Kuraflow Document Sans。PDF 中完整嵌入该子集（约 5.9 MB）以避免 fontkit 逐文件子集导致缺字；字体在首次导出时加载，界面本身不预加载。PDF 是可选择文字的矢量文档。
- 最小核对：保存价格/现价分离、含税和未税混合、未知单价与税额、门店/月份过滤、演示排除；JS/CSS 解析；浏览器实际 PDF 下载；三页样例逐页渲染检查。未运行完整业务测试、未部署。

## 数据核对范围

用户提供截图含「老魏木屋烧烤」和两笔订单。可控制的同址浏览器会话只返回初始示例门店，工具安全限制禁止读取 Codex 主窗口。本轮未伪造/重建木屋的数据，统计动态绑定当前页面保存的数据。无法独立核验这两笔订单的具体金额。

## 后续上线阶段

当前本地预览可统计本机保存的全部订单。云端既有 /api/state 对已送达历史记录有加载上限；正式发布本结算模块前，需要配套完整历史账期查询/分页，避免将有限已加载订单当作完整历史月结。本轮没有更改已上线系统。
