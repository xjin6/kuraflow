# 多语言界面

界面语言按中文、日文、英语、越南语排列。管理端语言选择位于 Flow 右侧；平台端和门店端使用同一套站内下拉控件。首次使用中文，之后在当前浏览器内按端、厨房及个人账号保留选择。

## 平台开关

在平台端打开中央厨房的「功能配置」，可以开启或关闭多语言。开关适用于该厨房的管理端及下辖门店端。关闭后界面回到中文，选择器置灰；重新开启后恢复之前的语言偏好。平台自身可使用四种语言。登录前尚未识别厨房，因此登录页也提供语言选择。

`GET /api/ui-features` 只读取当前登录身份所属厨房的配置。平台的保存操作复用 `POST /api/platform/flow`，增加可选的 `multilingualEnabled`；Flow 与多语言一起进行版本校验并原子保存。只修改语言开关不要求重新连接 Copilot。旧客户端不传语言字段时，保留已保存的语言开关。

迁移 `backend/migrations/0014_multilingual.sql` 已应用到正式 D1，Worker 与前端已发布。每度商事已开启多语言；其他厨房保持关闭，可由平台端在「功能配置」中开启。

## 翻译范围

翻译菜单、页面标题、按钮、表单标签、占位提示、日历、状态、校验与操作反馈。商品名称、门店名称、姓名、地址、报价方案名称、备注、待办正文、附件内容和聊天内容保持原文。CSV 协议字段和纳品书的已确认打印格式保持原约定。

分类、单位等控件可以显示译文，提交给后端的 `value`、业务枚举、ID、日期输入值和金额始终保持原值。

## 代码约定

- `src/i18n/locales/ja.js`、`en.js`、`vi.js`：以中文原文为键的三套词库。
- `src/i18n/index.js`：语言偏好、平台开关同步和显式翻译。
- `t(key, params)`：普通文本，用于提示、标题属性和显示格式化。
- `tx(key, params)`：HTML 文本翻译标记，语言变化时只更新被标记的文字。
- `ta(attribute, key, params)`：`title`、`placeholder`、`aria-label`、`alt` 的翻译标记。
- `mp(key, params)`：模板参数中属于系统文案的部分；普通字符串参数保留原文。
- `setI18nText(element, read, property)`：动态 UI 文字绑定；外部代码清除或改写文字后，旧绑定不会把旧错误重新放回界面。

不做全页面任意中文替换，不对业务字段调用翻译。新增文案先选合适的显示边界，再补齐三个词库；动态文案使用 `{0}`、`{1}` 参数。已经转义的业务参数按原值插入，不能把完整用户文本当作翻译键。

```sh
npm run check:i18n
npm run build:cloud
```

`check:i18n` 检查三个词库的键是否一致、占位符是否一致，以及当前明确引用的界面词条是否有遗漏。`scripts/i18n/localize-source.mjs` 是迁移旧页面的辅助工具；已标记的页面不允许再次自动改写，分段拼接的 HTML 应先整理为完整模板再处理。
