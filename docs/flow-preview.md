# Flow 部署与预览

Flow 是仅供管理端使用的侧边助手，基础版本已部署到正式站点。“平台统一配置”改动已于 2026-10-19 发布。平台提供按厨房的功能配置，不提供聊天；门店不显示 Flow。正式环境的对话、图片与加密授权保存在 D1。

入口：`http://localhost:8787/?page=overview&flow=1`。首次使用本地账号页的一键进入；登录后点击右上角通知旁的彩色 Flow 图标，桌面和手机均直接显示。图标使用共享矢量资源 `public/icons/flow-mark.svg`。

独立手机尺寸预览：`http://localhost:8787/__local-preview/phone?page=overview&flow=1`，以 420×912 CSS 视口显示真实页面，不改变桌面标签页尺寸。仅本地服务器允许页面由同源预览框加载，正式站点的框架限制保持原样。

## 能做什么

- 检索商品与规格、库存、采购成本、门店和报价、订单与配货备注、历史单据。
- 搜索和详情按实际登录厨房隔离，订单历史按页完整读取并校验修订号，不使用最近 100 单代替全部历史。
- 汇总已送达订单，保留未知单价；演示订单默认排除。
- 商品类别与饼图使用一次完整目录汇总，避免逐页遍历后再计算。
- 专门检查未报价单位、低库存和未设置库存。低库存结果标注阈值与基础单位。
- 回答流式显示，提供可点击的站内来源，支持停止、重试及页面跳转。
- 对话列表支持新建、切换、删除和撤销；对话与草稿按环境、厨房及个人账号隔离保存。刷新后可从列表继续，多个窗口有版本冲突时保留本页内容并提示。
- 要求出图时调用 `flow_render_visual`，直接展示图表、流程图和简单矢量插画，支持查看大图。图片按个人账号鉴权；不允许脚本、外部资源或任意 HTML。当前不提供照片类栅格生图。

## 附件识别与批量导入（2026-10-24，本地预览）

输入框左下角的回形针支持 PDF、xlsx、CSV／TSV、TXT、PNG、JPEG 和 WebP，也可拖入文件。每条消息最多 3 个文件，单个原文件不超过 10 MB；每份 PDF 最多 20 页，含扫描图的页面每轮合计最多 6 张。文字内容过大、加密 PDF、损坏文件和不支持的格式会明确报错，不静默截断后继续导入。xlsx 只读取已保存的单元格值，不运行公式、宏或外部链接。

浏览器通过本地托管的 PDF.js 提取文字和页码；扫描页及图片压缩成受限 JPEG，交给当前模型读图。xlsx 通过受限 ZIP／XML 解析保留工作表、单元格和行号。处理后保留文件名、提取文字及必要页图，原始 PDF／Excel 二进制不归档；回看附件展示的是识别内容。上传后的内容保存在 D1 `flow_attachments`，按厨房与个人账号鉴权，只保留小型引用在聊天和草稿中。原文件 10 MB 上限之外，服务端独立限制处理内容大小、图片格式、租户数量及总容量；重试相同上传编号不会重复保存。

本地 SDK 使用官方 blob 附件接口，线上 HTTP 适配器使用 Responses 的 `input_image` 或 Chat Completions 的 `image_url` 内容块；均只发送已授权上传的页面图与提取文字，不传本机路径或提供文件系统工具。明确不支持读图的模型会提示平台更换模型或使用文字版文件。

`flow_import_attachment_rows` 只在本轮有附件时提供，一张卡最多 20 行。每行先核对本站商品、规格、单位与门店，展示原值、新值及文件／页码来源。销售报价与采购成本必须区分，未知单价／税率不当零；库存工具设置的是实物总数。点击确认后由 `applyAttachmentRows` 复用现有报价、单位和库存规则，在一个业务修订号事务中提交全部行；失败或版本冲突不保存部分结果，取消不改业务数据。

本地已验证文字 PDF、Excel、扫描 PDF、CSV 与 JPEG 的实际上传及回看。真实 GitHub Copilot 模型已识别测试 PDF 和扫描图数值，并根据指定对应关系检索站内商品、门店，生成一张两行的报价／库存确认卡；该测试卡已取消，没有修改预览业务记录。确认成功、重复确认、跨租户／跨个人拒绝、冲突及取消路径使用隔离 D1 验证，HTTP 两种图像协议与 SDK blob 适配均有定向回归。

新增 `backend/migrations/0013_flow_attachments.sql` 仅建立附件表与索引，本地启动自动应用。尚未执行生产迁移或发布；正式部署时须先备份并核对目标数据库，再应用此迁移。PDF.js 与 fflate 由项目依赖及锁文件固定版本，构建只发布 PDF 运行文件、CMap、标准字体及许可证，测试文件留在私有预览目录。

## 业务写入（2026-10-22，已发布）

Flow 已接入受控业务写入：新增、修改及删除门店，新增、删除及恢复商品，设置实物库存与销售报价，新增、删除及恢复手动待办，以及修改手动待办的期限或完成状态。已发布版本 `81522627-1d8b-4e49-ba88-382e6b599ee1`；按用户要求保留线上现有厨房的 Flow 关闭状态，后续由平台配置开通。线上事实以云端部署记录为准。

用户明确要求且资料齐全时，Flow 先核对并准备不可变的确认卡片。新增、删除、修改及恢复均由用户在回答结束后点击确认才执行；取消不更改业务数据。确认有效期为 30 分钟，确认时重新核对账号、厨房、Flow 权限及业务修订号。模型没有确认工具，聊天文字不能代替点击确认。新增门店需要名称、日本行政区、详细地址、联系人和电话；地区代码通过站内地址工具查询，缺少资料时先询问。门店保存后由现有账号模块开通负责人，负责人码不进入模型、聊天回执或对话历史。门店删除后停用登录、释放未用配额并保留历史；商品进入回收站，手动待办采用软删除，两者可恢复。账号管理、删除订单或历史单据、外部消息发送未作为写入工具开放。

写入复用业务命令及 D1 事务，保留库存、单位、税率、历史价格、审计和通知规则。会话、账号状态、厨房有效期、Flow 开关和配置版本在写入事务中再次校验；其他人修改了业务资料时返回冲突，要求重新查询，避免覆盖新资料。本地 SDK 与线上 HTTP 适配器共用这套执行入口。

每条用户消息保存稳定请求编号，同一消息的同一操作重试会复用原结果。断线后恢复时先读取真实保存回执；如果门店已保存但负责人开通中断，会继续完成开通。已保存的请求不能因模型重试时改变参数而再次新增；后续修改使用新消息。每轮最多准备 6 项业务写入，仍受总工具调用预算约束。

准备结果保存在 D1 `flow_proposals`，按厨房及个人隔离，不接受客户端改写内容；确认状态和业务命令在同一事务中提交。恢复对话时重新读取服务端卡片，重复确认复用实际回执。聊天显示可打开业务页面的保存回执，回答失败或停止后仍保留已保存结果。写入后重新加载业务索引，后续查询能读到刚才的修改；前端收到回执后刷新业务页面，并保留尚未提交的草稿。对话请求编号和回执在本地及线上对话存储中均保留，支持刷新后重试。

模型没有终端、文件、浏览器、MCP 或任意 SQL 工具。

## 模型连接

本地使用公开的 GitHub Copilot SDK `@github/copilot-sdk`；正式 Worker 使用独立 Copilot HTTP 适配器，支持实时目录中的 Responses 与 Chat Completions 模型。系统指令为原创业务助手规则，没有采用未公开源码。

平台端客户列表 → **功能配置**：按厨房设置 Flow 开关，粘贴 GitHub Token（常见前缀 `gho_`），读取模型目录并指定运行模型。连接成功不自动开启功能，需要保存功能设置。先验证 GitHub 身份和 Copilot 模型权限，成功才替换旧连接；失败保留原配置。Token 永不回显或写入浏览器存储。

管理端负责人和管理员均不能配置 Token 或模型。停用时右上角 Flow 图标保持可见但置灰；服务端拒绝聊天、工具、对话读取和配置请求，已保存历史不删除。生成中的请求定时检查权限，停用后约 1 秒内中止。管理端每 15 秒、重新聚焦时刷新开通状态。

本地和正式 Worker 共用权限、D1 加密连接和模型目录服务；本地推理仍由 SDK 执行，不继承其他应用或全局 GitHub 登录。本地会一次性迁移本项目原有私有连接到本地 D1，保留原文件和按厨房／个人保存的对话，不覆盖平台的显式设置，不向线上导入。

模型目录按厨房和连接版本缓存 60 秒；手动刷新直接请求 GitHub。网络及 502/503 短暂重试一次，临时失败保留上次目录并标注缓存时间与错误；401/403 清除失效目录。更换 Token 不复用旧目录，不使用虚构列表，不自动替换不可用的指定模型。其他 API Key 及管理端设备授权入口已移除。

生成回答时显示青蓝紫动态条及简短步骤摘要。摘要来自实际的数据加载、工具调用、结果数量和回复阶段，不转发模型的隐藏分析或完整推理。完成、停止或失败会结束动画，步骤记录随对话保存。

## 代码入口

- `src/features/flow/flow-ui.js` / `src/styles/flow-ui.css`：独立侧栏、流式 UI、来源和开通状态。
- `backend/flow-control.js`：平台功能配置、固定模型和权限策略。
- `scripts/flow/flow-local-runtime.mjs`：本地与共享权限服务衔接、SDK 适配及旧连接保留。
- `scripts/flow/flow-copilot.mjs`：官方 SDK、自定义工具白名单与每轮独立会话。
- `backend/flow-provider.js` / `flow-store.js`：实时模型目录、缓存、Token 加密存储。
- `scripts/flow/flow-archive.mjs`：私有对话保存、乐观版本控制、软删除及安全 SVG 图片。
- `src/shared/flow-data.mjs` / `backend/flow-tools.js`：租户绑定索引、完整历史与只读工具。
- `backend/flow-actions.js` / `flow-schema.js`：受控写入、地址查询、参数校验、保存回执及重试恢复。
- `backend/flow-prompt.js`：业务助手系统规则。

`/api/flow/*` 在本地由开发服务处理，线上由 `backend/flow-service.js`、`flow-provider.js`、`flow-store.js` 与 `flow-content.js` 处理。POST 校验来源，会话失效后停止工具查询；平台与门店身份被拒绝。每轮最多 12 次工具调用，共享 HTTP 总预算 180 秒，本地 SDK 推理另有 90 秒上限。中止或断开请求会停止模型。

参考：<https://github.com/github/copilot-sdk> · <https://github.com/github/copilot-sdk/blob/main/docs/auth/authenticate.md>

## 当前验证

业务写入使用隔离的真实 D1 和模拟模型工具调用验证，包括门店与负责人开通、修改资料、库存报价、手动待办、失败回滚、撤销授权与写入竞争、断线去重、共享 HTTP 路径和本地 SDK 适配入口。相关回归见 `tests/backend/flow-actions.test.mjs`、`tests/frontend/flow-ui.test.mjs` 及两套对话存储测试。未向生产业务数据添加验收门店。

Flow 数据、连接、对话持久化、图片、会话权限及前端交互均有针对性测试；未登录、门店、平台身份及跨站请求均被拦截。真实 Copilot 问答已调用工具并核实 146 个商品、5 家门店、本月无已送达订单，以及未设置库存的商品数量；来源可回到页面核对。模型的分析阶段不会传给聊天界面，最终回答会替换中间输出。

历史图片与对话保留。当前独立连接已实际返回 18 个 GitHub Copilot 模型；已通过最小回复和调用绘图工具的完整请求验证，流程图请求返回了图片与最终回答。没有读取或复用其他应用凭据。

运行 `npm run test:flow` 复查 Flow 测试。平台权限、模型目录缓存和本地衔接另有 `tests/backend/flow-control.test.mjs`、`backend/flow-provider*.test.mjs`、`tests/flow/flow-local-runtime.test.mjs` 与 `tests/frontend/platform-flow.test.mjs`。当前线上版本与发布验证见 `docs/cloud-deployment-status.md`。
