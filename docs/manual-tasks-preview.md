# 手动待办与截止日期

已于 2026-10-20 通过 Wrangler CLI 正式发布，版本 `4b42cd0a-a040-427f-9f98-415e56c914bc`。发布详情见 `docs/cloud-deployment-status.md`。

2026-10-21 的独立待办页面调整已随头像功能发布：左侧「经营概览」下方增加「待办事项」，经营概览移出待办列表。新页面分「系统推送」「手动记录」两个 tab，分别筛选且保留各自的筛选状态；菜单、直达地址、刷新及前进／后退均识别新路由。所有记录使用同一套事项／截止日期／右侧操作格式，来源及业务操作保持原逻辑。版本 `02c3dbe3-7b71-4165-9d4d-b3b26cbc21ae`。

「系统推送」显示当前业务派生的待办，支持异常、逾期、待配货、待出发、待补货筛选；「手动记录」显示手动新增的事项，支持未完成、逾期和已完成筛选。两个 tab 的计数均按各自未完成记录计算，已完成手动记录在子筛选中保留。独立页面直接展示当前筛选的完整列表，不再通过经营概览的五行摘要或弹窗查看全部。

手动记录右侧提供「新增待办」。表单包含事项（必填，120 字以内）、截止日期（必填，默认东京当天，可用共享日历修改）和备注（选填，500 字以内）。新增记录标注「手动」，可用右侧勾选框完成，并在「已完成」筛选中恢复。记录按当前厨房共享保存，门店不能读取或操作。

宽屏待办面板限制为 840px，内容、截止日期和右侧操作保持固定列对齐；手机中日期移到事项下方，勾选保留 44px 点击区域。日期按东京日历比较，过期未完成事项显示逾期天数并进入「逾期」筛选。点击手动事项的日期可改期，原内容与完成状态保持不变。旧记录不自动填日期，显示「设置截止日期」入口；系统订单沿用配送日期，库存预警没有真实期限时不臆造日期。

来源由入口确定：配货员输入缺货备注后，系统依据订单状态生成的待办始终标注「系统」。直接在待办区输入含有“缺货”的事项仍标注「手动」。系统事项保留原业务处理入口，不提供手动完成勾选框。

手动记录随既有厨房业务状态保存，复用命令幂等、修订号校验及原子事务，无数据库迁移。普通管理员可以操作本厨房待办，平台和门店业务命令均拒绝。请求不能指定来源、作者、时间或其他厨房。
