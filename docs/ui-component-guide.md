# 倉流界面组件规范

更新：2026-10-10。已发布至正式站点，版本 0ffd9578。

## 通用规则

跨页面控件的颜色、圆角、尺寸和交互状态统一由 `ui-system.css` 管理。业务样式文件负责各页面布局；后续新增页面复用通用组件，避免在各功能区分别定义按钮和输入框状态。

| 组件 | 桌面 | 手机 |
| --- | --- | --- |
| 普通按钮、输入框、日期框 | 高 40px，圆角 8px | 高 44px，圆角 8px |
| 列表动作、内联保存/取消 | 高 32px，圆角 8px | 高 36px，圆角 8px |
| 内容卡片 | 圆角 12px，统一边框和轻阴影 | 同桌面 |
| 弹窗 | 圆角 16px；头部、正文、底部使用一致间距 | 距视口至少 12px；正文独立滚动 |

- 主操作使用深绿实底；次操作使用白底边框；辅助操作使用透明底。删除采用红色语义，但尺寸和交互方式与其他列表动作一致。
- 相同角色的按钮共用 hover、focus-visible 和 disabled 状态；键盘焦点使用同一圈线。
- 卡片本身不是动作时，不做悬浮位移或制造可点击的暗示。
- 编辑操作只显示图标，保留描述性 aria-label，按钮距对应内容 4px；图标按钮为 28px，手机上为 32px。
- 总商品功能卡使用绿色，门店库存与报价功能卡使用蓝色；两者在选中与未选中时均可区分。
- 编辑、删除、加号等图标来自 `app.js` 的同一套 SVG，不混用字符画图标。
- 详情、单位设置、商品创建、门店创建、删除确认等复用 `modal()`；保持统一的头部关闭按钮、正文滚动和底部操作区。

## 表格与商品详情

- 商品信息与动作分栏。删除放在固定宽度的独立“操作”列，不接在规格文案后。
- 单位、库存与报价的编辑图标紧跟对应内容，不放到单元格远端。主行容器高 32px，字体 14px、行高 22px；商品名、单位、库存和额度使用一致文字基线。
- 商品表格内部不使用行分割线或操作列竖线，通过留白和悬停底色区分行。
- 宽表在小屏内横向滚动，不让操作列覆盖其他按钮；显示统一的横向滑动提示，并允许键盘聚焦表格容器。
- 总商品、门店报价、门店订货及回收站使用相同商品名按钮，点击或按 Enter 打开商品详情。
- 详情显示实际图片、规格、说明、单位换算、适用范围内的库存和门店报价；未知值仍保留待确认。管理员和门店分别展示自己的数据范围。
- 关闭详情、按 Escape 后，焦点回到触发商品名。保持现有删除、恢复、报价和历史订单规则。

## 门店新增与编辑的一致性

- 两个入口必须共用字段组件、排列、图片裁剪、必填与格式校验、地址组装逻辑。编辑只增加已有值回填、识别码和删除入口，以及不同的提交文案。
- 两者均使用「都道府县 → 市区町村 → 行政区（适用城市）→ 具体地址」，更换上级时清空下级。编辑不再使用单独的城市/完整地址文本框，也不再放宽联系人和电话的必填规则。
- 回填优先使用已有区划编号；完整旧地址可按准确匹配的区划名称拆分，无法识别的地址原文保留在具体地址中。保存保留区划编号和名称，避免二次编辑丢失结构。
- 本地已检查新增→编辑回填→保存→刷新、更换上级清空下级及旧地址回填；未进行全套测试、后端修改或部署。

- 使用石墨导航、浅银灰工作区和钢蓝操作色。统计数据共享一个开放区域，依靠字号、字重和对齐建立层次。
