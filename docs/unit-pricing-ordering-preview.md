## 报价逻辑

- 同一门店独立报价或选用方案内，目标单位有有效手动单价时优先使用。
- 未报价单位使用已保存的 `saleUnits.perBase` 换算。源单价 × 源单位每基础单位份数 ÷ 目标单位每基础单位份数，最终单价四舍五入至两位小数，继承来源税口径和税率。
- 多来源推算的价格或税口径不一致时，不任意选择；保持未报价，供管理员明确设置。
- 只使用仍在售卖单位中的来源。不解析不确定包装文字，不跨门店、跨方案补价；不读取成本当作售价。
- 换算结果按读取时计算，不写回、覆盖或批量迁移原报价。清空方案中的手动单价可恢复自动换算；没有可用来源则仍未报价。
- 方案管理显示「按某单位换算」；门店端只显示本店有效单价。服务端投影、下单、价格变更校验、Flow 查询共用一致逻辑。
- 订单保存下单时单价、税率及换算比例。后续修改报价不改历史订单；提交期间价格或比例变化拒绝旧报价。

## 数据与预览

开发阶段仅通过 SELECT 读取正式数据库中本次所需的商品、方案、价格、单位及门店关联。用户确认后仅发布代码和界面资产，未执行生产数据写入或迁移；完整数据库发布前后逐表内容一致。

独立预览位于 `http://localhost:8788`，使用 `ACCOUNTS_PREVIEW_NAMESPACE=order-unit-review`。数据副本、校验结果和运行文件在被 Git 忽略的 `private-preview/order-unit-review/` 中，保持原 `8787` 本地数据库。该副本包含本轮所需商品和报价，后续从已有本地导入归档校验并补入 70 张商品图片，用于图片尺寸验收；未复制生产登录凭据、订单或联系方式。自动生成的本地负责人身份只用于一键预览。

启动：`ACCOUNTS_PORT=8788 ACCOUNTS_PREVIEW_NAMESPACE=order-unit-review npm run dev:accounts`。命名空间已有库时不会再次导入 `seed.json`；未设置命名空间时仍沿用原本地数据路径。
